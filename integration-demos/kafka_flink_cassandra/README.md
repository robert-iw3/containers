# Kafka → Flink → Cassandra

A holistic big-data streaming pipeline that combines three of the Apache stacks in
this repo — **Kafka** (ingest), **Flink** (stream processing), **Cassandra**
(storage) — reusing each directory's assets rather than duplicating them.

```
 producer            Kafka                Flink                 Kafka            sink            Cassandra
 (kafka/         →  iot-metrics    →   windowed agg +    →   sensor-rollups  →  cassandra_  →  telemetry.
  producers/)        topic             anomaly flag           topic             sink.py        sensor_rollups
```

- **Producer** — `../../kafka/producers/produce.py` emits JSON events (telemetry / orders / …).
- **Flink job** — generated by `../../flink/pipelines/build_pipeline.py` from a YAML
  config in `flink_jobs/`: a Kafka source → tumbling-window aggregation (+ z-score
  anomaly) → Kafka sink. Same generator as the flink directory, just Kafka connectors.
- **Sink** — `sinks/cassandra_sink.py` consumes the rollup topic and upserts into
  `../../cassandra/schema/schema.cql`'s `telemetry.sensor_rollups`.

The Flink↔Kafka connector jar lives in `flink-lib/` (mounted into the Flink cluster).

## Run it

```bash
./run_demo.sh telemetry        # IoT sensor telemetry (end to end into Cassandra)
./run_demo.sh orders           # pizza-order revenue (different app, different data)
```

`run_demo.sh` brings up a lean single-node-per-tier cluster (Kafka KRaft broker,
Cassandra node, Flink JobManager+TaskManager), creates the topics, applies the
schema, generates + submits the Flink SQL job, then runs the producer and the sink.

## What's verified

Live end-to-end (podman): the **telemetry** scenario runs producer → Kafka → Flink →
Kafka → Cassandra, landing hundreds of windowed rollups in
`telemetry.sensor_rollups` with the anomaly flag set on injected outliers. The
**orders** scenario runs producer → Kafka → Flink → Kafka (`order-rollups`),
producing per-shop windowed revenue — the same config-driven Flink stage handling a
completely different data shape with no code change.

## Scenarios (different applications, different data)

| scenario | source topic | Flink aggregation | rollup topic | Cassandra table |
|---|---|---|---|---|
| `telemetry` | iot-metrics | 10s tumbling: avg/min/max/count/stddev + anomaly per sensor+metric | sensor-rollups | `telemetry.sensor_rollups` |
| `orders` | pizza-orders | 30s tumbling: sum/avg/max/count revenue per shop | order-rollups | `telemetry.order_rollups` (see `flink_jobs/demo_schema.cql`) |

Add a scenario: drop a `<name>_to_cassandra.yaml` in `flink_jobs/` (source topic,
schema, window, aggregations, sink topic) — the Flink generator does the rest.

## Relationship to the full clusters

This demo runs one node per tier for a laptop-friendly end-to-end run. The
production, multi-node, TLS'd, autoscaling deployments live in their own directories
(`../../kafka`, `../../flink`, `../../cassandra`) — each with k8s manifests, Ansible
roles + Molecule, and tests. Point the producer/Flink/sink at those clusters'
bootstrap/contact endpoints to run the same pipeline at scale.
